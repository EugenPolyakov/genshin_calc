# Компактная сериализация: артефакты v5, ротации v4

Сохраняется существующее кодирование целых чисел в base26: заглавные буквы
продолжают число, строчная буква завершает его. Значения 0..25 занимают один
символ. Массивы и внешняя версия CalcSet не меняются. Artifact и Rotation имеют
собственные версии: Artifact — 5, Rotation — 4. Артефакты версий 1..4
и ротации версий 1..3 по-прежнему читаются.
Старые версии приложения не могут прочитать новый формат, поэтому обновления
чтения и записи нужно выпускать вместе. Массовая миграция сохранённых записей
не требуется.

## Артефакт

Структура: `[5, setId, rarityLevel, slotId, mainStatId, count, ...substats]`.

- `rarityLevel = (5 - rarity) * 21 + level`. Любой уровень артефакта 5★ занимает
  один символ. Для меньшей редкости требуется не более двух символов — столько
  же, сколько занимали два отдельных поля. Для каждой редкости сохраняются все
  ранее допустимые уровни 0..20.
- Каждый дополнительный атрибут представлен парой `[metadata, value]`.
- `metadata = statId + 16 * (initialValue + 5 * unactivated)`.
  ID атрибутов должны быть меньше 16; initialValue равен 0, если стартовый прок
  неизвестен, или 1..4. Флаг unactivated равен 0 или 1.
  Метаданные занимают не более двух символов и заменяют ID, стартовый прок
  и необязательный маркер неактивности. Ограничение на ID проверяется тестом.
- Младший бит value по-прежнему отличает проки (1) от числового значения
  атрибута (0). Для числовых значений сохраняется прежняя точность:
  целые числа или десятые доли.
- Проки сохраняются номером комбинации с повторениями. Модель артефакта
  уже сортирует проки, поэтому перестановки одного набора имеют один номер.
  Стартовый прок хранится отдельно в metadata.
- Таблица строится для числа вариантов прока N (2, 3 или 4): сначала комбинации
  длины 1, затем 2 и так далее до 6. Внутри каждой длины комбинации идут
  лексикографически, индексы проков не убывают. Нумерация начинается с 0
  и не зависит от порядка записей в БД. Например, при N = 4:
  0 → [0], 1 → [1], 2 → [2], 3 → [3], 4 → [0, 0], 5 → [0, 1].
- Число комбинаций равно сумме C(N + k - 1, k) по k от 1 до 6:
  27 для N = 2, 83 для N = 3 и 209 для N = 4.
  В массив записывается `2 * номер + 1`; для N = 4 максимум равен 417,
  то есть двум символам base26. Длина восстанавливается вместе с комбинацией.
  Номер за пределами таблицы считается ошибкой.
- Для v4 сохранено прежнее декодирование биективной системы счисления;
  версии 1..3 также читаются по своим прежним правилам.
- `getLexHash()` сохраняет прежний формат и правила сравнения.

Тестовый артефакт с четырьмя дополнительными атрибутами занимает 17 символов
вместо 23 в v3. Это отдельный пример, а не измеренное среднее по пользовательским
сборкам.

## Ротация

Каждый заголовок `[disabled, collapsed, type]` заменяется числом
`(type - 1) * 4 + disabled + 2 * collapsed` в диапазоне 0..15.
Остальные поля, зарезервированные свойства, счётчики и рекурсивная структура
не меняются. Экономия составляет ровно два символа на каждый сериализованный
элемент, включая вложенные. Некорректные или пропущенные элементы больше
не оставляют в потоке отдельные поля флагов без соответствующего элемента.

## Рассмотренные альтернативы

Все сочетания редкости и уровня невозможно упаковать в один символ base26:
таких сочетаний больше 26. Приоритет артефактов 5★ позволяет хранить самый
распространённый случай одним символом, сохраняя остальные значения.

Битовая упаковка с последующим кодированием в base64url позволила бы уплотнять
данные поверх границ отдельных целых чисел. Универсальное сжатие могло бы
использовать повторы в ротациях. Оба подхода потребовали бы нового внешнего
кодирования и более широких изменений для поддержки совместимости; кроме того,
универсальное сжатие добавляет накладные расходы на коротких записях.
Для полученной экономии эти изменения не требуются.

Булевы условия по-прежнему хранятся списками ID включённых условий. Битовая маска
может быть короче, когда включено много условий, но требует стабильного
ограниченного пространства ID и может расходовать лишнее место, если включённых
условий мало. Список ID не считается универсально оптимальным решением.

## Проверка

`test/Serialization.js` проверяет старые версии, сочетания редкости и уровня,
варианты и количество проков, стартовые проки, флаги, заданные вручную значения,
сохранность следующих данных в массиве, вложенные ротации, данные действий
и условий, а также полную сборку с пятью артефактами.

Все 162 теста прошли при передаче параметров Babel непосредственно в Jest.
Проверены все номера комбинаций для N = 2, 3 и 4 и совместимость с v4.
Существующая команда `npm test` завершается ошибкой на Node 26, поскольку
babel-jest.config.js использует экспорт CommonJS внутри пакета, объявленного
как ES-модули. Этот конфиг не относится к изменению формата и оставлен без правок.
